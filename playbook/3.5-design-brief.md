# Playbook Step 3.5: Design Brief

> Sits between Prescribe (step 3) and Renovate (step 4). Translates the prescribed archetype + modules into a one-page visual identity brief that the renovator implements as the brand's bespoke component set.

## Purpose

Prescribe (step 3) decides *what to build* (archetype, modules, framework). Renovate (step 4) builds it. The design brief is the in-between artifact: *what it looks like and why*.

Without this step, sites pass token review and still read as boilerplate, because token decisions (forge-brand) don't constrain page composition, signature visual moves, imagery direction, motion, or iconography. Those decisions get made implicitly during Renovate, with predictable failure mode — every section looks like the same card pattern repeated.

## What the brief contains

A **one-page document** per project at `<project>/brand/visual-identity/brief.md` with five sections:

### 1. Signature

The single load-bearing visual move that recurs across pages and gives the site visual continuity. One signature per brand. Examples:

- **instrument-readout** — information rendered as instrumentation. Bordered cards with mono labels, metric-display headers, mono cited-source footers, schematic diagrams replacing decorative imagery. Used when voice is technical/precise/receipt-driven. (TNA's signature.)
- **editorial-italic** — slab-serif headlines with italic emphasis in accent color on the load-bearing concept. Used when voice is editorial/considered/publishing-register. (Stripe Press adjacency.)
- **gradient-mesh** — abstract gradient surfaces as recurring background element. Used when voice is energetic/marketing-forward. (Vercel adjacency.)
- **stamped-monogram** — typographic mark with single-accent terminator (`TNA.`) used as masthead and recurring brand surface in place of a logo. Pairs with most signatures; works standalone for publishing brands.
- **schematic-diagram** — hand-drafted SVG diagrams (1.5px stroke, mono labels, no decoration) as primary content, not decoration. Used when the brand sells methodology or architecture work.

Pick one. Two signatures dilute each other.

### 2. Compositions per page

For each page in the site, name 2–5 compositions in execution order. Examples of named compositions:

- `hero-with-receipts` — eyebrow + headline + body + mono pill row of quantified claims
- `signature-readout-row` — 2–4 readout cards carrying the signature in concentrated form
- `case-study-stripe` — single-line numbered work entries with mono stack tags
- `closing-thesis-panel` — card-panel with italic emphasis on load-bearing concept
- `data-table-instrument` — instrumentation rendered as content (operator column + receipt column)
- `schematic-diagram-inline` — full-width inline SVG diagram replacing prose

The brief names the compositions; the renovator implements them as bespoke per-brand components.

**Composition-order rule**: the second composition on each page determines whether it reads as agency or documentation. Lead with hero, follow with a signature-bearing composition (not editorial prose), close with a thesis or CTA.

### 3. Imagery direction

Three lines:
- **Texture/hero**: scan-line trace / abstract gradient / photographic / illustrated / none
- **Diagrams**: hand-drafted SVG (deterministic, editable) or AI-generated (statistical, re-rollable)
- **Portraits**: photographic / monogram tiles (deferred) / abstract avatars

Reference the `image-gen` style system to use, if AI-generated.

### 4. Motion budget

Three lines:
- **Static by default** or **scroll-reveal by default** or **entrance-animated by default**
- **Hover**: lift+glow / color-shift / none
- **Reduce-motion fallback**: required

### 5. Iconography

Two lines:
- **Style register**: schematic-mono-line / filled-humanist / geometric-minimal / drafting-symbols / none
- **Source**: hand-drafted SVG / Lucide / Heroicons / Phosphor / custom

## How to author it

Cross-reference the brand-kit (forge-brand output) against an adjacency reference set (3–5 real sites the buyer's prospects already occupy). The brief is the synthesis: which signature, which compositions, which imagery, which motion, which icons make this brand belong in that adjacent visual neighborhood.

Audit checks before signing off:

- Does the signature appear on at least 4 pages?
- Does every page use 2–5 compositions (no fewer, no more)?
- Does the imagery direction reinforce the signature, or fight it?
- Does the motion budget match the brand voice register?
- Does the iconography subordinate to the signature?

## What the brief does NOT contain

- **Tokens.** Those live in forge-brand's `brand-kit.json`. The brief consumes tokens; it does not define them.
- **Component code.** Components are bespoke per brand, in the brand's repo. The brief specifies them by name and role; the renovator implements them.
- **Speculative patterns.** If a composition is not used on a real page in this brief, it does not appear in this brief. Patterns are extracted from shipped work, not authored speculatively.

## Output

A single `<project>/brand/visual-identity/brief.md` file, plus its supporting docs if needed (`recon.md`, `references.md`). The brief flows into Renovate (step 4), where bespoke components get authored against it.

## Anti-pattern: skipping the brief

Sites that pass token review and still read as boilerplate skipped this step. Symptom: every section is a stack of the same card pattern; no visual continuity across pages; the site reads as documentation regardless of brand. Cure: stop, write the brief, then renovate.

## Why this is a forge-site stage, not a separate tool

The brief is a delivery-pipeline scoping output, not a separate discipline. Tools are reserved for layers with their own contracts: forge-brand produces token JSON, forge-signal produces voiced content, image-gen produces imagery files. The brief is just a document the renovator reads — same shape as `requirements.md` from step 1 or the module list from step 3. It belongs in the playbook, not in a sibling tool.

This was the right answer from the start; a separate `forge-design` tool was an unnecessary abstraction.
