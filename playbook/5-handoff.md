# Playbook Step 5: Handoff

## Purpose

Deliver the finished site to the client with everything they need to operate independently. The site should run without you. If the client can't update content, check revenue, or handle basic issues alone, the handoff is incomplete.

## What the Client Receives

### 1. Deployed Site
- Production URL on Vercel (custom domain configured)
- Preview URL for staging changes
- SSL certificate (automatic via Vercel)
- Analytics running (Vercel Analytics dashboard)

### 2. Content Management (if CMS)
- Sanity Studio URL (`domain.com/studio` or `project.sanity.studio`)
- Sanity account credentials (their own login)
- Brief guide: how to edit pages, add blog posts, update team members
- Content types documented (what each field does)

### 3. Payment Dashboard (if Stripe)
- Stripe Dashboard access (their own account)
- Where to see revenue, subscriptions, disputes
- How refunds work (process in Stripe, webhooks handle the rest)
- Test mode vs live mode explained

### 4. Email (if Resend)
- Resend dashboard access (for delivery monitoring)
- Where form submissions go (which email address)
- What automated emails are sent and when

### 5. Domain & DNS
- Where the domain is registered
- How DNS is configured (Vercel nameservers or CNAME)
- SSL renewal: automatic on Vercel, no action needed

### 6. Documentation
Generated by claude-docs-toolkit:
- Architecture overview (for future developers)
- Environment variable reference (what each one does, where to get it)
- Deployment guide (how to deploy changes)
- Content guide (how to use the CMS)

## Client Training Checklist

Walk the client through these operations:

### Content Updates
- [ ] Edit an existing page in Sanity Studio
- [ ] Add a new blog post / article
- [ ] Add a new team member / service / event
- [ ] Upload and crop an image
- [ ] Publish changes (and understand draft vs published)

### Business Operations
- [ ] View analytics in Vercel dashboard
- [ ] View revenue in Stripe dashboard
- [ ] Process a refund in Stripe
- [ ] Check form submission emails
- [ ] Access billing portal (if subscription model)

### Emergency Procedures
- [ ] Site is down → check Vercel dashboard for deployment status
- [ ] Form emails not arriving → check Resend dashboard for delivery issues
- [ ] Payments not working → check Stripe dashboard for webhook failures
- [ ] Need to make the site inaccessible → Vercel dashboard > pause project

## Ongoing Maintenance Model

### What's Automated (No Action Needed)
- SSL certificate renewal (Vercel)
- CDN cache invalidation on deploy (Vercel)
- Analytics data collection (Vercel Analytics)
- Webhook processing (Stripe → app → database)

### What the Client Handles
- Content updates via Sanity Studio
- Responding to form submissions / inquiries
- Processing refunds when needed
- Monitoring Stripe for disputes (email notifications)

### What Requires a Developer
- Adding new features or pages
- Changing payment tiers or pricing
- Updating framework or dependency versions
- Fixing bugs or handling edge cases
- DNS or domain changes

## Success Criteria

The handoff is complete when:
- [ ] Client can edit content without help
- [ ] Client can check revenue without help
- [ ] Client knows who to contact for developer-level changes
- [ ] All credentials are in the client's possession (not yours)
- [ ] Documentation is delivered and reviewed
- [ ] Client has confirmed everything works from their end
